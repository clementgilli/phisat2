Key Concepts

Tasks

Tasks are defined in phisat2/tasks/specs.py. Each task specifies output size, target key, and loss family.

  • segmentation: pixel-level classification for lulc, lc, burned, clouds, and floods.
  • classification: image-level classification for fire.
  • pixel_regression: dense regression for roads and building.
  • global_regression: task type exists, but no datasets are registered yet.
  • pretrain_reconstruction: self-supervised reconstruction on triplets.
  • domain_adaptation: simulated-to-real feature alignment on triplets.
  • eval_domain_gap: compares teacher/student encoders with downstream decoders.
  • eval_encoder: latent-space evaluation on lulc.

Models

Models are defined in phisat2/models/registry.py.

  • phisatnet: student CNN encoder for pretraining, domain adaptation, and downstream tasks.
  • terramind_v1_tiny, terramind_v1_small, terramind_v1_base, terramind_v1_large: TerraTorch teacher backbones.

Downstream and pretraining builds use ComposedModel: encoder output goes directly to PhiSatNetDecoder for spatial tasks or MultiScaleClassificationHead for classification-like tasks.

Data Loaders

Data loaders are defined in phisat2/data_loaders/registry.py.

  • downstream: Zarr downstream datasets with image and task-specific target keys.
  • triplets: simulated PhiSat-2, real PhiSat-2, Sentinel-2, masks, and tile IDs.
  • synthetic: random tensors for smoke tests and CI-style checks.

CLI Orchestration

The CLI in phisat2/cli/cli.py handles:

  1. Parse command-line arguments for fit, test, and registry listing commands.
  2. Auto-select triplets for paired tasks.
  3. Resolve task specifications from task and dataset.
  4. Build datamodule, model bundle, and Lightning module.
  5. Run Lightning Trainer with callbacks, logger, and hardware config.

knowledge_distillation is registered, but _build_module raises NotImplementedError for it.

Hardware Configuration

The AUTO_DDP flag asks the CLI to select DDP when multiple CUDA devices are available and accelerator/devices/strategy are still auto.

  • Multiple CUDA GPUs: accelerator=gpu, devices=<count>, strategy=ddp.
  • Single CUDA GPU: accelerator=gpu, devices=1.
  • Otherwise: the explicit or default Lightning hardware settings are used.

Output Structure

Training outputs are written to:

  checkpoints/
    best.ckpt
    last.ckpt
  wandb/

Evaluation writes to:

OUTPUT_DIR/TASK/DATASET/MODEL/SUBSET/eval_seed_N/
  test_metrics.json
