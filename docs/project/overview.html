Key Concepts

Tasks

Defined in phisat2/tasks/specs.py. Each task specifies:

  • Output size (number of classes or regression targets)
  • Target key in batch dict (mask, label, target, etc.)
  • Loss function (cross-entropy, MSE, KD loss, etc.)

Task types:

  • segmentationcode>
  • classificationcode>
  • pixel_regressioncode>
  • global_regressioncode>
  • pretrain_reconstructioncode>
  • distillation_kdcode>
  • domain_adaptationcode>
  • eval_domain_gapcode>

Models

Defined in phisat2/models/registry.py. Two patterns:

Shared Decoder Models

Most models use this pattern:

  1. Encoder (e.g., phisat2_geoaware, terramind_*, prithvi_*)
  2. FeaturePyramidAdapter normalizes outputs to 4-level spatial pyramid
  3. Task head (SharedUNetDecoder for spatial tasks, GlobalPoolingHead for global tasks)

This allows different encoders to share the same decoder contract.

Full-Structure Models

myriad2_full_unet is a complete U-Net with embedded decoder.

Data Loaders

Defined in phisat2/data_loaders/registry.py. Three types:

  • downstreamcode>
  • tripletscode>
  • syntheticcode>

All produce batches with batch["image"] and batch[spec.target_key].

Training Module

The phisat2/training/ directory contains Lightning modules for different training paradigms:

  • downstream.pycode>
  • pretrain_ssl.pycode>
  • distillation_kd.pycode>
  • domain_adaptation.pycode>

Each module is a Lightning LightningModule with standard PyTorch training loops.

CLI Orchestration

The CLI in phisat2/cli/cli.py handles:

  1. Parse command-line arguments (task, model, dataset, dataloader, etc.)
  2. Resolve task specifications from task/dataset pair
  3. Build model, datamodule, and Lightning module
  4. Run Lightning Trainer with callbacks, logger, and hardware config

For paired tasks (SSL, KD, DA), the dataloader is auto-detected from the task type.

Hardware Configuration

The AUTO_DDP flag automatically detects available GPUs:

  • Multiple GPUs: Lightning DDP with automatic device setup
  • Single GPU: Single-GPU training
  • CPU: Fallback to CPU training

Override with ACCELERATOR, DEVICES, and STRATEGY variables.

Reproducibility

All randomness is controlled by phisat2/utils/seed.py:

  • Python, NumPy, PyTorch, CUDA deterministic modes
  • Lightning worker seeding
  • Per-seed checkpoint separation

Seeds are specified via SEEDS Make variable (e.g., SEEDS="0 42 100").

Output Structure

Training outputs are written to:

OUTPUT_DIR/TASK/DATASET/MODEL/seed_N/
 checkpoints/
 best.ckpt        # Checkpoint with min val_loss   
 last.ckpt        # Final checkpoint   
 logs/
 metrics.csv      # Training/validation metrics per epoch
